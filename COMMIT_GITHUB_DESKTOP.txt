🔒 Segurança e Performance: RBAC + Otimização de Pool de Conexões

📋 Resumo
Esta commit implementa melhorias críticas de segurança e performance, incluindo controle de acesso baseado em roles (RBAC) completo e otimização do pool de conexões do Supabase para evitar esgotamento e downtime.

🔐 Segurança - RBAC Implementado

✅ Rotas Administrativas Protegidas
• POST /api/admin/fix-data - Agora requer role 'admin' (verifyToken + checkRole)
• POST /api/ceasa/import - Agora requer role 'admin' (verifyToken + checkRole)
• POST /api/auth/register - Mantida com checkRole(['admin'])

📁 Arquivos: backend/server.js, backend/routes/ceasa.js, backend/authController.js

⚡ Performance - Otimização de Pool de Conexões

🎯 Problema: Pool esgotando (15-20 conexões), causando downtime de 5-10 minutos

🔧 Soluções:

1. ✨ Singleton Pattern para Prisma (backend/utils/prisma.js - NOVO)
   • Limita conexões: connection_limit=5
   • Evita múltiplas instâncias
   • Graceful shutdown

2. 🛡️ Circuit Breaker Pattern (backend/utils/circuitBreaker.js - NOVO)
   • Protege contra sobrecarga
   • Abre após 5 falhas, timeout 60s
   • Estados: CLOSED → OPEN → HALF_OPEN

3. 🐍 Otimização Python (ai-service/utils/database.py)
   • pool_size: 5 → 3
   • max_overflow: 5 → 2
   • pool_recycle: 3600s → 1800s (30 min)
   • Total: máximo 5 conexões Python

4. 🏥 Health Check Melhorado (backend/server.js)
   • GET /health testa banco + circuit breaker
   • Status: 'ok' ou 'degraded'

5. 🔗 Integração Circuit Breaker
   • Todas queries críticas protegidas
   • backend/server.js, authController.js, routes/ceasa.js
   • backend/services/* atualizados para singleton

📊 Resultado: 10-20 conexões → 4-10 conexões (~50% redução) ✅
